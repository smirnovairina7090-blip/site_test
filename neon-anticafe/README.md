# ✳ NEON DEN — неоновое интернет-антикафе

**Полнофункциональный учебный проект для демонстрации возможностей курса Python PRO.** Яркий адаптивный интерфейс, API на Python (Flask) и настоящая база данных SQLite.

## Что умеет сайт

- Показывает 8 игровых станций в трёх категориях с ценами.
- Проверяет свободные места на выбранную дату, время и продолжительность через API.
- Принимает бронирования и **защищает от двойной брони** пересекающихся интервалов (транзакция в SQLite).
- Показывает код подтверждения; позволяет найти свою бронь по коду.
- Содержит неоновый бар: фильтрация меню, корзина, изменение количества товаров.
- Отправляет заказ на сервер, где **цены пересчитываются на Python**, а заказ сохраняется.
- Работает на телефоне, планшете и компьютере.
- Не запрашивает телефон, email, карты и не принимает платежи. Все данные и брони демонстрационные.

## Запуск на компьютере

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Перейдите по адресу **http://127.0.0.1:5000**.

Для тестов из корня проекта:

```bash
python -m unittest discover -s tests -v
```

## Где Python, а где фронтенд?

- `app.py` - бизнес-логика, SQL, API, валидация запросов.
- `templates/index.html` - структура страницы.
- `static/css/style.css` - визуальный стиль и адаптивность.
- `static/js/app.js` - общение с сервером, модальные окна, корзина.
- `tests/test_app.py` - тесты настоящих серверных функций.

**Учебная траектория:** дизайн интерфейса → JavaScript-события → JSON и HTTP → маршруты Flask → SQLite → бронирование без конфликтов → API-тестирование.

## Развёртывание

Для постоянного хранения бронирований запускайте Flask на обычном сервере с постоянным диском и задайте переменную `DB_PATH` с путём к файлу SQLite. Для production рекомендуется добавить WSGI-сервер (Gunicorn), резервное копирование и защиту публичных эндпоинтов от злоупотреблений.

Проект совместим с Vercel Flask runtime (`vercel.json`). **Ограничение:** файловая система Vercel Functions временная. На Vercel по умолчанию используется `/tmp/neonden.sqlite3`, но созданные брони и заказы могут исчезать после перезапуска функции, а при нескольких инстансах быть несогласованными. Для долговременной работы на Vercel нужна внешняя БД (Postgres/managed database). Это демонстрация, не коммерческий сервис бронирования.

## Python Control Room v2.0 (для показа родителям)

Откройте **`/control`** после запуска проекта. Это интерактивная панель реального Python-бэкенда, а не просто макет:

1. Нажмите **«Загрузить демо-сценарий»**: SQLite получит 10 записей с вымышленными именами.
2. В разделе **«Брони и заказы»** запускайте и завершайте игровую сессию, меняйте статус заказа: принято → готовится → готово → выдано. Переходы контролирует конечный автомат в `control.py`; невозможные переходы получают HTTP 409.
3. Откройте **«Журнал событий»**: каждая операция записывается через SQL в таблицу `activity`.
4. Проверьте **«Бонусный клуб»**: за каждые 100 ₽ заказа Python начисляет 1 XP, записи хранятся в `members`.
5. Подберите станцию **«Алгоритмом Python»**: сервер анализирует бюджет, тип активности, длительность, цену и занятость, затем сортирует варианты по оценке.
6. Нажмите **GET /dashboard** в API-инспекторе и покажите JSON, который отдаёт Python серверу интерфейса.
7. На главном сайте забронируйте место в будни с 12:00 до 16:00, чтобы увидеть тариф **DAY BOOST −15%**. В баре используйте промокод **NEON10** для **−10%**. Сервер всегда считает скидку самостоятельно.

### Важно про безопасность и данные

Это **общедоступный учебный деморежим**, в Control Room намеренно нет входа, поэтому здесь **нельзя хранить реальные данные гостей** или использовать сайт для настоящих покупок. Не вводите личные данные. Для коммерческого проекта нужно добавить роли и авторизацию, защиту от CSRF и флуда, внешнюю постоянную БД, отдельные среды и тесты безопасности. На Vercel локальная SQLite хранится во временной `/tmp` и **может сбрасываться или отличаться между запросами** (несколько серверных экземпляров). Чтобы изменения всегда сохранялись, запустите Flask на постоянном сервере или подключите внешнюю БД.

Тесты: `python -m unittest discover -s tests -v`. Проверяются цены, бонусы, блокировка коллизий, переходы состояний и идемпотентность демо-данных.
