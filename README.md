# Дневник достижений Креайтивики

Личный дневник на восемь занятий: сборка компьютера, бинго, шесть наград и записи тем уроков. Цветное изображение компьютера открывается после восьми деталей. Каждая деталь и награда выдаётся отдельным кодом преподавателя.

## Работа ученика

1. При первом открытии нажать «Создать мой дневник» и сохранить автоматически созданные логин и пароль.
2. Войти с ними на любом устройстве. Данные хранятся в базе D1 и доступны только в своём аккаунте.
3. Заполнять данные, даты, темы уроков, итоги и бинго. Записи сохраняются автоматически; состояние сохранения показано сверху.
4. Получать коды преподавателя и открывать соответствующие детали и медали. Коды проверяет сервер, изменение полей не позволяет назначить себе награды.
5. После всех 23 галочек показать дневник преподавателю и получить подарок.

## Запуск

Node.js 22.13 или новее. Установить зависимости штатным установщиком проекта, затем `npm run dev`. Поддерживается Vinext в Cloudflare Workers и постоянная база Cloudflare D1. Это приложение с сервером; GitHub Pages сам по себе не поддерживает вход и общую базу данных.

`.openai/hosting.json` содержит D1 binding `DB`. Схема в `db/schema.ts`, миграции в `drizzle/`. Секрет среды `UNLOCK_CODE_HASHES` должен содержать JSON-объект с SHA-256 от кодов в верхнем регистре без пробелов и дефисов. Ключи: `part-1`...`part-8`, `level`, `idea`, `explain`, `friend`, `voice`, `skillspace`. Коды хранятся отдельно у преподавателя и не публикуются в репозитории. Имена переменных в `.env.example`.

Для локального запуска записать секрет в игнорируемый `.dev.vars`, сгенерировать и применить миграции по инструкциям поставляемого стартера. Для публикации через Sites используется штатный процесс сборки, синхронизации исходников и применения миграций. Локальные и опубликованные данные разделены.

## Проверка

- `npx tsc --noEmit`
- `node --experimental-strip-types --test tests/model.test.ts`
- `node tests/api-integration.mjs` с локальным файлом кодов преподавателя, указанным в `DIARY_TEST_CODES_PATH`.
- `npm run build`

Интеграционные проверки выполняют регистрацию, вход из новой сессии, изоляцию учеников, сохранение тем, проверку неверного кода, все 14 разблокировок, повторное применение кода, запрет самоназначения наград и выход. Пароли хешируются PBKDF2-SHA256 с индивидуальной солью. Сессии используют HttpOnly cookie и серверные записи. Подбор кодов и паролей ограничен.

## Файлы

- `app/page.tsx` и `app/globals.css`: интерфейс и адаптивная вёрстка.
- `app/api/[...path]/route.ts`: аккаунты, сессии, сохранение и коды преподавателя.
- `public/assets`: сгенерированные изображения компьютера и наград, логотип и шрифты.
- `public/diary-a4.pdf`: печатный горизонтальный дневник.

Учебные поля, темы и бинго можно менять самостоятельно. Подтверждённые детали и награды сохраняются отдельно и не снимаются случайным нажатием. Для входа нужны сохранённые данные: автоматического восстановления пароля без отдельной настройки школы нет.

## GitHub Pages

Страница ученика опубликована в основной ветке репозитория, в папке `achievement-diary`: https://smirnovairina7090-blip.github.io/site_test/achievement-diary/

`node scripts/build-github-pages.mjs` создаёт статическую сборку `dist-pages/`. Она использует те же компоненты и оформление, что и основная версия. URL изображений и PDF относительные, чтобы корректно работать в папке GitHub Pages. `github-pages/Diary.tsx` и `github-pages/style.css` формируются из основной версии автоматически.

`api-bridge/` содержит отдельный сервис Vercel, который подключает GitHub Pages к существующей базе учеников. Браузер не обращается к домену ChatGPT. Данные входа, записи и коды преподавателя общие для обеих версий. Для GitHub Pages используется токен личной сессии; пароль ученика и коды преподавателя не сохраняются в браузере. CORS разрешает только домен GitHub Pages владельца. Произвольные внешние адреса и действия через сервис недоступны.

Проверка моста: `node --test api-bridge/bridge.test.mjs`. Публикация API производится в проект `creitivika-diary-api` команды `smirnovairina7090-8722s-projects`. Готовая статическая сборка помещается в `achievement-diary/` основной ветки с сохранением остальных проектов репозитория.
